# 1. QUÉ ES SIN LÍNEA

Sin Línea es un medio informativo digital automatizado.

No funciona alrededor del concepto tradicional de “noticia”.

El objeto principal del sistema es el:

`EVENT`

o **suceso**.

Una publicación detectada en una fuente no constituye automáticamente una nueva noticia.

Puede ser:

* una señal de un suceso nuevo;
* una fuente adicional de un suceso existente;
* una repetición;
* una confirmación;
* una contradicción;
* una corrección;
* una actualización.

Ejemplo:

25 medios publican sobre un choque entre dos colectivos.

Sin Línea NO debe generar 25 noticias.

Debe existir:

`1 event`

con:

`25 source_items / evidencias`

asociadas.

El artículo público es simplemente una representación actual del conocimiento disponible sobre ese `event`.

---

# 2. PRINCIPIO EDITORIAL FUNDAMENTAL

Sin Línea no intenta imponer una narrativa.

Debe informar:

> qué ocurrió, qué sabemos, quién sostiene cada información y qué todavía no sabemos.

Prioridad editorial:

**precisión → claridad → contexto → brevedad**

No utilizar:

* clickbait;
* dramatización;
* framing político;
* adjetivación editorial;
* lenguaje partidario;
* interpretación moral;
* opiniones del medio;
* inferencias no respaldadas.

No existen “hechos positivos” o “hechos negativos”.

Existen hechos.

El lector los interpreta.

---

# 3. PRINCIPIO TÉCNICO FUNDAMENTAL

La arquitectura objetivo es:

**monolito modular + workers asíncronos**

No microservicios.

No Kubernetes.

No infraestructura innecesaria.

La aplicación debe comenzar sencilla y poder separarse posteriormente si la escala lo requiere.

Además:

> código para lo determinista; IA solamente cuando hace falta interpretar, comparar, clasificar o redactar.

No utilizar LLMs para resolver problemas que una comparación, query SQL, hash o regla simple puede solucionar.

# 5. UNA ACLARACIÓN CRÍTICA SOBRE LAS FUENTES

Las noticias siempre nacen inicialmente desde las **fuentes vigiladas que yo configure manualmente**.

No quiero un crawler recorriendo todo Internet continuamente buscando noticias.

## Funcionamiento correcto

Yo cargaré manualmente fuentes como:

* medios;
* organismos;
* municipios;
* agencias;
* sitios públicos;
* etc.

Estas son las:

`MONITORED SOURCES`

Son nuestro radar.

El sistema consulta esas fuentes periódicamente.

Cuando aparece una publicación nueva:

1. se ingesta;
2. se detecta el posible suceso;
3. se comprueba si ya existe;
4. recién entonces comienza la investigación web sobre ese suceso.

La investigación web sí puede recorrer Internet y descubrir otras fuentes.

Ejemplo:

`Rosario3` está vigilado.

Rosario3 publica:

> Chocaron dos colectivos en Pellegrini y Corrientes.

Sin Línea detecta el suceso.

Entonces busca:

* Municipalidad;
* La Capital;
* Cadena 3;
* redes oficiales;
* otra prensa local;
* fuentes primarias;
* etc.

Estas nuevas fuentes pueden utilizarse como evidencia aunque **no sean fuentes vigiladas**.

# 6. FUENTES DESCUBIERTAS ≠ FUENTES VIGILADAS

Cuando una investigación encuentra una fuente nueva útil:

debe poder guardarse en `sources`.

Pero:

`is_monitored = false`

por defecto.

Registrar una fuente NO significa comenzar a vigilarla.

Solo yo decidiré desde Admin qué fuentes pertenecen al radar permanente.

Ejemplo:

```text
source:
  name: Página 12
  domain: pagina12.com.ar
  method: RSS
  feed_url: ...
  is_monitored: false
```

Si posteriormente yo la habilito:

```text
is_monitored = true
```

recién entonces entra al radar.

Esta separación es obligatoria.

# 16. ROLES CONCEPTUALES DE IA

La configuración objetivo es:

### Procesamiento ligero

**GPT-5.6 Luna**

Responsabilidades:

* extracción;
* clasificación;
* entidades;
* fechas;
* normalización;
* generación de JSON;
* relevancia;

---

### Embeddings

**Voyage 4**

Uso:

* representación semántica;

---

### Duplicados ambiguos

**GPT-5.6 Terra**

Solo cuando reglas y embeddings no permitan determinar con suficiente confianza si dos señales pertenecen al mismo suceso.

### Resolución barata de claims

**DeepSeek V4 Pro**

Debe ser la primera capa de interpretación de claims.

Determina principalmente:

* soportado;
* una sola fuente;
* conflicto;
* incertidumbre;
* posible información obsoleta;
* necesidad de investigación adicional.

---

### Verificación escalada

**GPT-5.6 Sol**

Solo para claims difíciles.

Nunca enviarle automáticamente todas las noticias completas.

---

### Redacción

**Claude Sonnet 5**

Recibe información estructurada.

No debe utilizar artículos originales libremente como material editorial.

---

### Auditoría

**GPT-5.6 Sol**

* cuándo;
* protagonistas;
* tipo;

# 21. DEDUPLICACIÓN

La decisión debe utilizar tres niveles.

## Nivel 1 — Código

Comparaciones deterministas:

* tiempo;
* lugar;
* entidades;
* tipo de hecho;
* URL;
* hashes;
* campos normalizados.

---

## Nivel 2 — Voyage

Comparar embedding del EventCandidate con Events recientes.

Definir thresholds configurables:

```env
EVENT_MATCH_HIGH_THRESHOLD=
EVENT_MATCH_LOW_THRESHOLD=
```

No fijar números mágicos en múltiples archivos.

---

## Nivel 3 — Terra

Solo cuando:

```text
LOW_THRESHOLD <= similarity < HIGH_THRESHOLD
```

o cuando existan señales contradictorias.

Terra recibe:

* candidato;
* 2-5 Events candidatos;
* metadata esencial.

Debe devolver:

```json
{
  "decision": "EXISTING_EVENT | NEW_EVENT",
  "event_id": "...",
  "confidence": 0.0,
  "reason": "..."
}
```

# 23. ESTRATEGIA DE INVESTIGACIÓN

No queremos:

> las primeras 10 URLs de Google.

Queremos diversidad y evidencia útil.

Buscar preferentemente:

1. fuente primaria u oficial;
2. medio cercano al hecho;
3. otra fuente independiente;
4. documentos o datos públicos;
5. fuentes adicionales solo cuando aporten algo.

La investigación termina cuando nuevas búsquedas dejan de aportar información material.

En el MVP puede existir un límite configurable de búsquedas para controlar costes.

Ejemplo:


# 28. CUÁNDO NO SOBREVERIFICAR

Ejemplo:

Tres medios locales reportan un incendio.

Todos coinciden en:

* lugar;
* hora aproximada;
* existencia del incendio.

No necesitamos llamar a Sol para preguntarle:

> ¿realmente hubo un incendio?

Si las fuentes difieren:

Fuente A:

`2 muertos`

Fuente B:

`3 muertos`

y no existe información capaz de resolverlo:

NO llamar repetidamente a modelos intentando fabricar certeza.

El estado correcto puede seguir siendo:

`CONFLICTING`

y el artículo debe decir:

> Las fuentes consultadas informaron cifras diferentes, de entre dos y tres fallecidos.

La incertidumbre es un resultado válido.

```text
Buscar:

- estadísticas;
- documentos;
- entrevistas.
```

* claim;
* evidencia encontrada;
* contexto necesario.

* cuerpo.
