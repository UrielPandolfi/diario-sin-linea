# Decisiones vigentes

Solo políticas con evidencia de intención (spec, test que las fija, comentario en código o `.env.example`). El cableado y los leftovers están en `STATE.md` y `pipeline.md`; no preservar un comportamiento solo porque existe.

## Producto y arquitectura

- La unidad es el **suceso** (`Event`); el artículo es la representación actual. Varias publicaciones pueden ser evidencia del mismo hecho (modelos `Event` / `EventSource` / `SourceItem`).
- Monolito modular + workers Celery; no microservicios.
- Código determinista para gates, locks, identidad e índices; LLM para extraer, comparar, clasificar, redactar o auditar (`editorial_gate.py`, `pipeline_lock.py`, `providers/`).

## Publicación

- Se publica si la **auditoría final de la versión que se publica** está aprobada: último run de `auditing` **completado** (`SUCCESS` o `FAILED`, no `latest_success` a ciegas), `status=SUCCESS`, `audited`, `passed=true`, `version_after == current_version`, y el `evidence_snapshot` atado a esa versión no viola invariantes estructurales. Ausente, FAILED, desparejado, `coverage_gap` / `central_unverified` obligatorio o snapshot de otra versión → no publica (fail-closed). `version_after` reasignado no transfiere un `passed` de otro texto. Tests: `test_failed_audit_after_pass_does_not_approve`, `test_version_change_between_audit_and_publish_blocks`, `test_alberto_coverage_gap_blocks_optimistic_and_attribution`, `test_optimistic_auditor_cannot_silence_structural`.
- MVP: `AUTO_PUBLISH=true` + Audit `passed` + no `editorial_hold` → el worker encola `publish_event_article` para la V1 y para actualizaciones. `AUTO_PUBLISH=false` + Audit `passed` → `READY_FOR_REVIEW` (publicación manual). Durante Writing/Audit de una V2 el live sigue en `published_version` anterior; V2 solo pasa a live tras Audit passed y publish. Tests: `test_auto_publish_true_enqueues_first_and_update`, `test_auto_publish_false_leaves_ready_for_review`, `test_published_update_keeps_live_until_passed_audit`.
- La portada (`hero_image_url`) es presentación: se genera **después del commit** de publish/revise en una `SessionLocal` propia (`HeroImageService.ensure_in_own_session`). Fallo de renderer o persistencia no revierte `PUBLISHED`. Fase A usa `TemplateHeroRenderer` (Pillow 1200×630); es el fallback permanente de una futura generación de fondo. El front público la muestra en detalle y cards (feed, live, búsqueda). Tests: `test_renderer_failure_does_not_revert_publish`, `test_persist_flush_failure_does_not_revert_publish`, `test_feed_and_search_cards_include_hero_url`.

## Gate editorial

- Ámbito: asuntos públicos y país `editorial_country_code` (default `AR`), salvo `argentina_relevance` (`evaluate_editorial_gate`, `test_editorial_gate.py`). Política nacional/provincial fuera de Rosario **pasa** en tests. El README que dice “solo Rosario” está desactualizado.

## Identidad en dedup

- Código para igualdad/contradicciones estructuradas; embeddings (Voyage) para similitud semántica; DeepSeek (`AMBIGUOUS_DEDUP`, mismo adapter que claims) para identidad ambigua. No se mantienen sinónimos de vehículos, parsers de colisiones ni reglas específicas de otros dominios. El esquema actual no aporta identificadores únicos del suceso: el fast-path conservado es la URL ya vinculada; `_level1_match` no acredita identidad para URLs distintas. Coincidir en tipo, localidad, fecha, dirección o entidades no demuestra el mismo Event (`dedup_identity.py`, `test_detection_dedup.py`).
- `compare_identity` solo devuelve contradicciones entre país/provincia/localidad presentes y diferentes, o direcciones explícitas reconocidas de formatos comparables. Se conservan normalización de espacios/caso/tildes, prefijos de calle e intersecciones invertidas. Ausencia de contradicción no es prueba de identidad. Los Events contradictorios se excluyen antes de seleccionar por score alto o consultar el LLM; se consideran otros candidatos y el LLM solo ve un par compatible. High/low siguen en 0.88/0.72.
- Si el mejor embedding queda **por debajo de LOW**, no hay auto-merge. Si el par no es claramente distinto —`event_type` compatible, sin conflictos de `compare_identity`, sin años de proceso disjuntos, y con señales de coincidencia (anclas de proceso distintivas **o** entidades nombradas compartidas; **no** exige provincia/localidad extraídas)— se llama a DeepSeek. En la banda LOW–HIGH, Voyage ya filtró: se llama salvo contradicción o tipos incompatibles. DeepSeek devuelve `SAME_EVENT` (asocia), `DIFFERENT_EVENT` o `UNSURE` (ambos crean Event nuevo). `_level1_match` sigue devolviendo `None`. Tests: `test_below_low_with_signals_asks_deepseek_without_extracted_province`, `test_deepseek_unsure_creates_new_event`, `test_distinct_civic_processes_below_low_do_not_go_to_terra`, `test_clear_automerge_skips_deepseek`.
- Sin veto temporal determinista: `occurred_at` no informa precisión, origen explícito/inferido ni duración/puntualidad del suceso. No se deducen esos atributos mediante regex ni se reemplaza el umbral retirado de dos horas por otro. Los timestamps permanecen en el payload del LLM; no se agregan modelos ni clasificadores temporales.
- El LLM recibe contexto mínimo del candidato y del Event existente (mismos campos factuales, similitud Voyage y señales descriptivas). Vincular una fuente no actualiza título, resumen ni embedding del Event durante matching. Pruebas con fakes; Voyage/DeepSeek reales se cubren en smokes, no en CI.

## Artículo y versiones

- Un `Article` por `event_id` (`uq_articles_event_id`).
- Update material sobre un publicado: working copy `DRAFT`; el live sigue en `published_version` hasta un audit aprobado (`writing_service.py`, `test_published_update_keeps_live_until_passed_audit`).
- Issues del audit autónomo viven en `pipeline_runs.metadata_json` (`audit_service.py`). `Correction` se crea en revisión editorial (`editorial_service.py`), no en el loop Sol→rewrite.
- El LLM de auditoría (Sol) dictamina lenguaje, sesgo y **certeza de la redacción** respecto del snapshot de esa versión. Recibe titular, bajada, cuerpo, bloques y un `evidence_posture` compacto (más `headline_claim_candidates` para titular/bajada, que no tienen `claim_refs`). No recibe fuentes crudas, búsquedas ni Verification para reabrir hechos. Citas atribuidas no se neutralizan. Aprobar lenguaje no certifica hechos: `structural_findings` + `merge_audit_result` siguen en código. Tests: `test_audit_payload_keeps_raw_sources_out`, `test_audit_flags_evaluative_voice_and_rewrites`, `test_optimistic_auditor_cannot_silence_structural`, `test_writing_certainty.py`.
- `SINGLE_SOURCE` puede publicarse; no puede afirmarse como hecho categórico en titular, bajada ni lead, ni combinarse varios para sintetizar una proposición más fuerte. Writing debe atribuir o calificar, no borrar el dato. Audit HIGH: `UNSUPPORTED_CLAIM` (`single_as_corroborated`), `ATTRIBUTION` (`attribution_lost` / `utterance_as_truth`), `INFERENCE` (`semantic_shift`). Un cuerpo bien atribuido no sana un titular categórico. `passage_is_attributed` reconoce el stem `atribu` (atribuyó / atribuido / atribuidos) y el condicional `habría`/`habrian`. Tests: `test_writing_certainty.py`, `test_audit_policy.py`.

## Concurrencia y providers

- Un solo `RUNNING` entre writing, auditing y publishing (índice en `0009_publishing.py`, `pipeline_lock.py`, pre-check admin).
- Anthropic no es auditor: `registry.py` rechaza `AUDITING` + anthropic; `.env.example` lo documenta.
- Provider y model ID por env (`core/config.py`); el dominio no hardcodea IDs de vendor.
- Detection: `event_type` clasifica exclusivamente el suceso principal informado, identificado primero en `what_happened`; no antecedentes, contexto histórico, delitos de fondo, causas anteriores, biografías ni hechos secundarios. No exige actualidad: una muerte antigua determinada como homicidio puede ser `homicidio`; un acto judicial en una causa por homicidio clasifica el acto judicial. Se conserva el string libre y se usa `otro` si el tipo no es seguro, sin inventar hechos. Contrato y ejemplos A–E (incluido San José 1111): `test_prompt_payloads.py`. La validación manual con el provider real se documenta en HANDOFF; no se incorpora a CI ni se reclasifican Events existentes automáticamente.

## Claims y evidencia (con tests)

- Merge por `assertion_key` / agrupación por `comparison_key`. La identidad del claim (quién dijo qué, con qué valor) no se fusiona con la identidad de la proposición: un acto de habla usa `comparison_key` sobre el objeto declarado; un hecho posterior puede ser otro claim. El detector trata la misma proposición (mismo `comparison_key` o misma fecha de calendario en el suceso) como `proposition_corroborated` (conocimiento, no reescritura) si el valor coincide. Una declaración histórica no se marca `OUTDATED` porque un documento posterior traiga otra cifra. Tests: `test_declaration_and_underlying_fact_keep_distinct_assertion_keys`, `test_detector_same_date_new_claim_is_proposition_not_new_high`, `test_official_figure_keeps_distinct_identity_from_historical_declaration`.
- Extracción incremental: el prompt es `identity_only` (sin `title_internal` ni cifras del Event). Una magnitud de 4+ dígitos no se persiste si no aparece en el snippet/cuerpo de la fuente nueva (`INVALID_EXCERPT`); no se exige extraer cada número trivial. Tests: `test_incremental_keeps_historical_figures_and_persists_new_official_values`.
- Un hit de búsqueda de Verification no se asocia como `EventSource` solo por aparecer en Search. Hace falta un juicio persistible útil (`SUPPORTS` / `CONTRADICTS` / `QUALIFIES`) **y** que el ítem no nombre una jurisdicción distinta a la del suceso. `DOES_NOT_ESTABLISH` no se persiste; `MENTIONS` puede quedar como evidencia de claim, no como fuente del suceso. Un SUPPORTS de otra provincia que solo coincide en un dato genérico queda `ClaimEvidence`, no entra a `source_payloads`. Tests: `test_off_topic_search_hits_stay_candidates_not_event_sources`, `test_other_jurisdiction_generic_overlap_is_evidence_not_public_source`, `test_declaration_runs_claim_queries_not_event_research`.
- `SUPPORTED` exige al menos **dos procedencias informativas demostradas y distintas**. Origen conocido: cita explícita a un primario (`cited:`), documento constitutivo (`constitutive:`), reprint distintivo del pasaje (overlap ≥0.85 y ≥12 tokens), o **periodismo propio** (`reporting:{source_id|host}`) solo con HTML extraído y fetch no fallido. Un `document_key` o dominio distinto **no** es independencia. Si hay señal explícita de origen común (agencia enmarcada, comunicado, fuente atribuida identificable), prevalece `wire:` / `comunicado:` / `attributed:` aunque los textos difieran. Reprint por excerpt **y** fingerprint del cuerpo (no del título). Sin prueba: grupo `unknown`; unknown no suma. Clamp (`clamp_supported_status`): si `requires_authoritative_source`, solo `authoritative_independent≥2` sube a SUPPORTED; si no, `known_independent≥2` basta. Hay SUPPORTS (unknown o known=1) → SINGLE_SOURCE, no UNCERTAIN. No hay umbral `source_count≥2`. Tests: `test_independent_reporting.py`, `test_supported_two_distinct_domains` (dos hosts + excerpt corto → SINGLE_SOURCE), `test_two_proven_information_origins_can_be_supported`, `test_same_outlet_two_items_is_single_source`, `test_two_original_urls_same_informative_source_are_not_two_corroborations`, `test_three_unknown_documents_do_not_count_as_independent`, `test_reprints_and_blogs_are_not_independent_corroboration`.
- Utterance **después** de desambiguar: `authentic_primary` SUPPORTS documenta **«X dijo Y»** (SUPPORTED del dicho; CHECKED con primaria auténtica o, si no hace falta registro, con `independent_reporting`). `attributed_report` no satisface `primary_source_required` del utterance ni hereda CHECKED al contenido de Y. Claim mixto (dicho + vigencia/alcance) sin split: no excepción de primaria única; requisito más estricto. La declaración de quien dicta una resolución (jueza) es un claim distinto de la decisión; un excerpt de la condena o la suspensión no respalda el dicho. Si el excerpt del LLM no está en el cuerpo, se intenta un fragmento literal del documento (`salvage_excerpt`); no se relaja `excerpt_in_source`. Cobertura central completa solo si ese utterance está cubierto. Un solo medio → `SINGLE_SOURCE`. Tests: `test_extracted_transcript_supports_utterance_not_content`, `test_video_search_hit_only_is_not_authentic_primary`, `test_attributed_report_is_not_authentic_primary`, `test_refine_plan_clamps_utterance_away_from_boletin`, `test_bregman_split_selection_and_utterance_plan`, `test_judge_utterance_kept_when_excerpt_is_in_body`, `test_judge_utterance_coverage_gap_without_body_excerpt`.
- `requires_authoritative_source` (código, no el LLM) fija cuándo hace falta un registro: documento, cifra material (costo, pérdidas, patrimonio, presupuesto, tarifa, estadística oficial; no un recuento observable de incidente), alcance/vigencia normativa, acusación de verdad, contenido de expediente/fallo, proposición mixta. Utterance no mixto: False (la cifra dentro de «X afirmó Y» no hereda primaria). Presentación de denuncia: target judicial, sin primaria. `apply_primary_requirement` ya no exceptúa `SUPPORTED` + conteo de reporting; solo primaria o `authoritative_independent≥2`. Designación, tarifas reguladas, fallos y cifras materiales siguen exigiendo primaria (fixtures Federman/tarifas/Mendoza/`material_normas`). Tests: `test_independent_reporting.py`, `test_verification_plan.py`.
- `SUPPORTED` + `independent_reporting` puede dar CHECKED solo si hay `claim` en `is_strong_verification` y **no** `requires_authoritative_source` ni `looks_sensitive_accusation` (fail-closed si falta el claim o si la clasificación falla). Un upgrade a primaria (`found_relevant` / `authentic_primary`) sustituye el kind, no lo duplica. La tarjeta no muestra «No se localizó una fuente primaria…» salvo democión `missing_documentary_primary`. Tests: `test_sensitive_accusation_not_checked_from_independent_reporting`, `test_claim_card_presentation.py`.
- `unresolved=false` si la política fijó un status (incluida democión Sol→SINGLE_SOURCE). `final_reason` es de código; `llm_reason` es trazabilidad. Test: `test_sol_optimistic_keeps_policy_reason_and_resolved_false`.
- La tarjeta pública serializa un DTO de presentación (`claim_card_presentation`, leído en `compact_public_claims`) a partir de `status` + `support_basis` + `demotion` + tipos de evidencia. No re-corre `assess_origins`. Histórico o par desparejado: cobertura desconocida, sin inventar conteos. Un claim sin evaluación completa de Verification (`evaluation_state` distinto de `complete`, o sin decisión) no usa copy de independencia evaluada; el público ve «Aún no verificado». Nunca `llm_reason` al público. `SINGLE_SOURCE` evaluado no convive con copy de corroboración independiente plural. Tests: `test_claim_card_presentation.py`, `test_sol_optimistic_keeps_policy_reason_and_resolved_false`.
- En el artículo público, status + presentation + labels salen del `evidence_snapshot` atado a `published_version` (`view_from_evidence_snapshot`), no del par live. `PublishService` sigue eligiendo `published_version = current_version` de la versión que publica; una Verification posterior no cambia el GET hasta un publish de esa versión. Admin (`_claims_out`) y analytics siguen en `verification_view_for_event`. Tests: `test_public_claims_freeze_presentation_and_labels_to_published_snapshot`, `test_public_article_claims_follow_published_snapshot_not_live_verify`, `test_track_b_contradiction_is_material_and_freezes_public_claims`.
- Contrato `editorial-evidence-1` en `pipeline_runs.metadata_json`: par claim_run↔verify_run (`claims_fingerprint` + `based_on_claim_run_id`). Writing, labels y `is_strong_verification` leen ese par, no la última SUCCESS suelta por stage. Corridas históricas sin fingerprint: `unknown`; no CHECKED sobre verify desparejado. `ClaimDecision.evaluation_state` es opcional (`complete` | `skipped` | `pending` | `failed`); ausencia = unknown/legacy, nunca `complete`. Toda corrida SUCCESS nueva deja una entrada en `decision_by_claim_id` por claim del evento (evaluado o skip de policy/budget/veto/outside_recheck). No cambia `ClaimStatus` ni convierte skip a `UNCERTAIN`/`SINGLE_SOURCE`. Writing compacta solo decisiones completas/legacy; no lleva `evaluation_state` al prompt. Snapshot legacy con decisión almacenada y sin `evaluation_state`: copy evaluado solo si no es skip-shaped (`llm_reason` en veto/policy_skip/budget/outside_recheck); lo justifica `support_basis`/`status` de `_decision_after_policy` y la ausencia de ese reason. La sola presencia de la clave no prueba evaluación. Tests: `test_new_extract_plus_failed_verify_does_not_reuse_prior_approval`, `test_verification.py`, `test_editorial_evidence.py`, `test_skip_shaped_legacy_decision_is_not_evaluated_copy`.

## SEO público

- Origen canónico: `SITE_URL` (URL absoluta, sin slash final). No usar `API_URL`, `VERCEL_URL` ni el Host del request cuando `SITE_URL` está definido. Tests: `apps/web/lib/seo/seo.test.ts`.
- El slug del artículo se asigna al crear el draft y no cambia al actualizar titular/resumen/cuerpo. URL pública: `/noticias/{slug}`. Lookup por `public_id` redirige 308 con `permanentRedirect()`. Test: `test_domain.py` (slug estable).
- Solo es indexable lo público: `published_at` + `published_version` + no archivado. Drafts y `READY_FOR_REVIEW` sin live no salen por la API pública ni por `GET /api/v1/sitemap-articles`. Tests: `test_public_api.py`, `test_sitemap_articles.py`.
- `sl_locality` personaliza el feed; no es gate de crawl. `/`, `/en-vivo` y `/buscar` se sirven sin cookie. `/buscar` es `noindex, follow` y no va en `Disallow` de robots.txt.
- Deploys con `VERCEL_ENV` distinto de `production` reciben `X-Robots-Tag: noindex, nofollow`. Si `VERCEL_ENV` no existe, no se aplica ese escudo.
- Title y description de una noticia son el titular y el summary editoriales. No hay keywords ni títulos SEO paralelos.
